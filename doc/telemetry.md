# Telemetry

PRX by Nebuless collects gateway usage reports and installer events at
`https://prx.nebuless.cloud`. Gateway reports also check for updates.
`nebprx run` and `nebprx join` do not report independently, but
the installer reports even when installing a client rather than a gateway.

## Gateway reports

The gateway POSTs JSON to
`https://prx.nebuless.cloud/api/telemetry/v1/check` with these fields:

| Field | Value |
| --- | --- |
| `instance_id` | Persistent UUIDv7, generated once and stored in the gateway SQLite `telemetry_state` table |
| `version`, `git_sha` | Build version and Git SHA (`git_sha` omitted when empty) |
| `os`, `arch`, `go_version` | Operating system, CPU architecture and Go runtime version |
| `uptime_s` | Process uptime in seconds |
| `connected_devices_1h` | Count of devices seen in the last hour |
| `actions_count_1h` | Number of actions recorded in the last hour |
| `bytes_in_1h`, `bytes_out_1h` | Aggregate incoming and outgoing action bytes in the last hour |
| `transport` | `wireguard`, `tailscale`, or combined `wireguard+tailscale` (empty if neither is enabled) |

The persistent ID links reports across restarts. It is not a user identity.
If saving the ID fails, the current run uses it but a restart generates a new one.
Implementation: [`cmd/nebprx/telemetry.go`](../cmd/nebprx/telemetry.go).

The first report runs 30 seconds after gateway startup, then every six hours.
Requests run in a background goroutine with a five-second timeout. Network
failures are silent and do not block the gateway. Development builds
(`version = "dev"`) skip reporting, and the worker also drops dev reports.

The response contains `latest`, `your_version`, `update_available`, `url` and
`advisory`. Available updates produce a dashboard banner and a log message.
There is no automatic binary replacement or remote configuration control.

## Installer reports

Both `install.sh` and `site/public/install.sh` POST to
`https://prx.nebuless.cloud/api/telemetry/v1/install` on completion or failure.
They send `install_id` (random per invocation), `event` (`completed` or
`failed`), `os`, `arch`, `version` (requested tag or `latest`), `from_source`
(`0` or `1`), and `reason` (installer failure message, empty on success).
Requests are best-effort background calls with a three-second timeout.
The install command itself remains `https://prx.nebuless.cloud/install.sh`.

## What is not sent

Gateway telemetry sends no filesystem or request paths, machine or upstream
hostnames, request bodies or headers, rules, HCL configuration, profile names,
emails, cookies, tokens or credentials. Only aggregate traffic counts leave
the gateway. Installer reports contain the fields above, not configuration or
traffic data. Cloudflare sees the connection source IP, but the worker does
not write it to D1.

## Storage and access

The Cloudflare Worker in `site/worker/index.ts` writes to D1:

- `gateways`: one latest snapshot per instance, including first/last seen
  timestamps and the latest raw JSON payload (migration `0001`).
- `installs`: one row per installer invocation, updated for repeated events
  with the same ID (migration `0003`).
- `telemetry_snapshots`: daily aggregate history, generated by the scheduled
  handler at 00:05 UTC. It counts gateways seen in the preceding seven days,
  grouped by transport, platform and version, plus a total (migration `0002`).

Access is through authorized Nebuless Cloudflare/D1 credentials, not a public
per-instance API. Queries live in `site/sql/telemetry/` and can be run with
`npm run telemetry` from `site/`. Both POST routes accept at most 4 KB of
UTF-8 JSON. Oversized payloads return 413 and invalid payloads return 400.

Before deployment, create a D1 database in the Nebuless Cloudflare account,
set its ID in `site/wrangler.jsonc`, and apply migrations `0001`–`0003`.
Configure DNS and the worker route for `prx.nebuless.cloud`, then deploy the
worker before shipping binaries or installers that report there.

## Release source

The worker still reads
`https://api.github.com/repos/Nebuless/clawpatrol/releases/latest`, cached
at the Cloudflare edge for 30 minutes. Its response URL comes directly from
the release's `html_url`. Release bodies starting with `[security]` or
`[advisory]` supply the first paragraph as an advisory. The installers also
still download binaries from `Nebuless/clawpatrol` GitHub releases and clone
that repository for source builds. Nebuless has no releases yet.

## Opt-out

Disable gateway reporting and update checks with any one of:

- `telemetry = false` in `gateway.hcl`.
- `NEBPRX_TELEMETRY=0` in the gateway environment.
- `DO_NOT_TRACK=1` in the gateway environment.

Disable installer reporting separately with `NEBPRX_NO_TELEMETRY=1`:

```sh
curl -fsSL https://prx.nebuless.cloud/install.sh | NEBPRX_NO_TELEMETRY=1 sh
```

The gateway switches do not disable installer events, and the installer
switch does not disable gateway reports. Dismissing a dashboard banner
does not opt out.
